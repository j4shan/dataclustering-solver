SUBJECT
Data ingestion on a Databricks Lakehouse for one brand-sales stream.
The figure teaches one mechanism: a stream is grouped by brand_id and
pricing_tier, given a partition_id, and written to two Delta tables.
The narrow index keeps query-predicate features plus partition_id.
The wide event table keeps the full attributes plus partition_id plus
record_id. It is the illustration of Go Live on Databricks Lakehouse
§2.5. Partition assignment is a closed step on this figure; the
tracker method is stated on the left pane. It is not an allocator
and not a recommendation.

THE INSTANCE (fixed -- do not vary)
The renderer holds this as one dictionary near the top. Values printed
in the figure are derived from it; none is typed again in drawing code.
This dictionary is shared with
resources/img_prompt/c_dpp_skipping_prompt.txt. It is hypothesized.
It is not a provider corpus, a catalog score, or a measured workload.

stream = "brand sales"

group_keys = ["brand_id", "pricing_tier"]

# predicate features are exactly the group keys
index_columns = ["brand_id", "pricing_tier", "partition_id"]

# full attributes plus the assignment and the identity
event_columns = [
  "brand_id", "pricing_tier", "sku", "amount",
  "partition_id", "record_id",
]

records = [
  {"record_id": "r01", "brand_id": "A", "pricing_tier": 1,
   "sku": "brk-12", "amount": 40, "partition_id": "p1"},
  {"record_id": "r02", "brand_id": "A", "pricing_tier": 2,
   "sku": "flt-03", "amount": 18, "partition_id": "p2"},
  {"record_id": "r03", "brand_id": "B", "pricing_tier": 1,
   "sku": "brk-08", "amount": 55, "partition_id": "p3"},
  {"record_id": "r04", "brand_id": "B", "pricing_tier": 2,
   "sku": "tyr-21", "amount": 22, "partition_id": "p4"},
]

Each record is one group in this instance: four (brand_id, pricing_tier)
pairs, four partition_ids, one row per pair. Those partition_ids are
the result after assignment; this figure does not derive them.

DERIVATION
  index_row(r) = {k: r[k] for k in index_columns}
  event_row(r) = {k: r[k] for k in event_columns}
  groups     = distinct (brand_id, pricing_tier) from records
  partitions = distinct partition_id from records

Fail the render if any record is missing a group key, a partition_id,
or a record_id, if two records share a record_id, or if the two tables
disagree on brand_id, pricing_tier, or partition_id for the same
record_id.

PRODUCTION
Draw at 3840 x 2160 and downsample once to 1920 x 1080 with LANCZOS.
Load SFNS.ttf and SFNSMono.ttf from /System/Library/Fonts; select
weight with set_variation_by_name and cache by (size, weight, mono).
Use anchor= for text. Draw arrowheads as line glyphs, not Unicode.

Both tables share row height and header height. Index columns align
with the same-named event columns on a shared vertical grid so a
reader can see what was dropped. Labels must clear arrow shafts by
at least 20 source pixels. Fail the render on clipping, overlap, a
bare column name, an index cell that is not in index_columns, an
event cell that is not in event_columns, a missing split of the
fan-out arrow, or an assignment box that prints a hash or a slot. After
rendering, read the PNG back and inspect it visually before
acceptance. The PNG at the accepted path is rendered and accepted
from this specification; the renderer that produced it is deleted
with acceptance. A later visual change starts a new authoring pass.
