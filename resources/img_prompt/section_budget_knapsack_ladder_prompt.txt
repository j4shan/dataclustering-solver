SUBJECT
The storage assignment from Drawing Storage Boundary §1 written as a
multiple-choice knapsack. The figure presents / introduces one mechanism: each leaf of
the price split is a class, each allowed geometric container count is an
option on that class's chain, and a later option is reachable only after
the chain has paid for the preceding count. Adjacent steps are priced in
estimated skipped records per added container. It is the illustration of
§2. It is not an allocator and not a recommendation.

Two chains, four options, three edges each. One chain still stands at the
initial single container; the other has advanced one step. The two steps
those chains could take next are compared, and the larger one is named.

  "Yes": {"records":  80000, "selected_per_query": [1, 0, 0, 1, 0, 0], "holds": 1},
  "No":  {"records": 400000, "selected_per_query": [3, 0, 2, 1, 3, 0], "holds": 4},

The two chains are a hypothesized hot/cold mix, not a partition of a
provider corpus, a catalog score, or any measured workload. Every state
and metric on this figure is hypothesized and then derived from the
dictionary above; the record counts are sized to make the ladder legible,
not to report a real table.

Both leaves must exceed container_capacity * max(container_options) =
64,000 records, so the top of the ladder is justified rather than
hypothetical. The generator fails if either leaf is smaller than that.
"holds" is the count each chain currently stands at.

DERIVATION (the generator computes all of it)
For a group with n records and K equal containers:

  p = mean(selected_per_query) / n
  np = n * p
  K_max = floor(n / container_capacity)
  lambda_K = np / K
  option_value(K) = n * exp(-lambda_K)          # n * Pr(X = 0)

An option is offered only when K <= K_max. On this instance every option
is offered on both chains: K_max is 80 for Yes and 400 for No, so no
blocked slot is drawn. For adjacent options:

  delta_K = K_next - K_current
  delta_V = option_value(K_next) - option_value(K_current)
  efficiency = delta_V / delta_K

A chain's taken edges are those reaching a count at or below "holds";
its pending edge is the one leaving "holds"; the rest are later edges.

Expected derived checks, rounded only for display:

       V(1)=57,323, V(4)=73,604, V(16)=78,351, V(64)=79,584
       e(1->4)=5,427, e(4->16)=396, e(16->64)=26
  No   n=400,000  np=1.5   K_max=400  holds=4   pending 4->16
       V(1)=89,252, V(4)=274,916, V(16)=364,204, V(64)=390,734
       e(1->4)=61,888, e(4->16)=7,441, e(16->64)=553

DIMINISHING RETURNS
This figure depicts the common case: on both chains each step buys less
per added container than the step before it. The marginal benefit of
n exp(-np/K) peaks at K = np/2, so a ladder starting at K = 1 is
diminishing throughout only when np <= 2; both chains satisfy that. The
generator fails if any chain's efficiencies are not strictly decreasing.
This figure shows no rising edge and prints no "not diminishing" tag.
