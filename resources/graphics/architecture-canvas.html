How a corpus becomes a score. Data flows top to bottom; every component is named by its module path so this page can be checked against the code rather than believed.

4 Load parsed once, reused by every layout

Loader

core/dataset.py

Classifies columns by role and returns a Dataset: features and blob size columns by name, summed byte totals, packed supports, query times and set names. Names no provider's column.

Packed support

core/packed_support.py

supp(e) as one bit per query, 64 to a word. Buys exactly two operations: OR-reduce member supports into supp(c), and popcount that into demand breadth dc.

validation queries cleared before hand-off
5 Assignment seam 2 — where a layout is decided

Training view

strategies/registry.py

build_view → TrainingView. Validation support bits are physically zero, so leakage is impossible by construction. Columns are reached by dynamic key: features[name], size_columns[name].

SEAM

Strategy plugin

strategies/registry.py · third-party

A registered callable: view in, one container id per event out, nothing else. Shipped: insertion_order and random_order — baselines that bracket what ordering alone is worth, reading no feature at all.

Layout check

core/layout.py

validate_and_compact — totality, non-negativity, then ids compacted to a dense range. The harness never inspects what a strategy did.

container_of_event · int per event
6 Evaluate the objective

Scoring

core/evaluate.py

A container is opened exactly when it holds an event the query selected. Per-query figures are accumulated, never materialized — no dense container × query matrix is ever built.

  • skip ratios — byte, record, container
  • waste ratio, read amplification
  • per-query waste median / p95 / max
  • size health from core/layout.py

Management cost

core/management_cost.py

A registered, replaceable model charging per-container bookkeeping, fragmentation and rebuild volume in abstract units. The simulator's own construct — not part of the formulation's objective, and plotted as a separate axis.

The sweep loop. Bands 5 and 6 run once per (strategy, target size) — 2 strategies × 8 container targets = 16 layouts, each emitting one row per training / validation / all, so 48 metric rows. Bands 3 and 4 run once: the corpus and its supports are invariant across every layout, which is why container assignment is a separate array rather than a column on the data.

Runner

bench/runner.py

run_one is the primitive; sweep iterates it. add_baseline_lift divides each waste ratio by the do-nothing layout's at the same target.

Metric table

bench/metrics.py

One CSV per run, concatenated on read. Append-only comes free from never rewriting a file — no database, no locking.

Three charts — KPI vs cost, KPI vs container size, skipping by month — rendered as a light and dark SVG pair each, then embedded in a standalone page.

Two lines this diagram exists to make visible

The contract line (band 3). Everything above it produces a dataset directory; everything below it consumes one. No module below band 3 names a column any provider chose — the roles are matched by pattern, which is what lets a production export be scored without an edit.

The layout line (band 5). The dataset is loaded once and is invariant; the layout is recomputed 16 times. Container assignment therefore lives in its own array keyed by event position, never as a column on the corpus — a distinction that decides how the whole evaluator is shaped.
