1. Working with Storage Container Limits

Once data split trees exposing high value potential are identified, those terminal groups still need a storage assignment a real data storage system can keep. Measuring Data Layout Fitness grows the grouping by cutting leaves and scores the grouping on data-skipping potential. The tree is a screen for where selection concentrates. Those groups then have to be assigned to containers the system can actually hold.

Problem Statement's medicine-cabinet walkthrough already names the limit that makes the assignment finite. Each small drawer is one storage container. The cabinet holds only so many drawers, so the dispensary cannot give every medicine its own drawer. A table in a data storage system meets the same count limit.

A storage container can be a local SSD block, a file, a partition, or an object in cloud storage. Every system pays metadata to keep each container addressable. Most systems therefore publish a container-count ceiling, such as a maximum number of files or partitions per table, and a soft container-size floor, such as a minimum byte size per S3 object.

The objective is a storage assignment plan that maximizes estimated data skipping inside those two limits. This page studies the maximum skipping potential of that plan as a multiple-choice knapsack on a static query sample. The numeric result is tied to that frozen profile and may not transfer to a live system. It can still mark a cost-versus-benefit threshold: how much extra skipping the next increment of container count appears to buy on the observed log.

term symbol meaning
terminal group g one population produced by the already-chosen logical split
group population ng number of events in group g
container count Kg number of containers assigned to group g
container-count ceiling B maximum number of containers the system will keep for the table
container-size floor smin smallest container the system will accept; it caps how large Kg can grow

Reserve one container for every terminal group so each group stays addressable. The remaining count up to the ceiling is what the groups share. The size floor (smin, defined in this section) bounds the finest packing a group may take.

Once group g is packed into Kg equal containers, each unit has size ng/Kg. Measuring Data Layout Fitness §3.1 scores a packed leaf with the empty-unit Poisson probability. This page uses that probability as a volume. The leaf benefit is the group's event count times the chance a packed unit holds no selected event.

term symbol meaning
group-wide rate pg average, across training queries, of the fraction of group g each query selected
selected count in a unit X how many events a later query selects in one packed unit of the group
Poisson parameter λg expected selected-event count in one unit, λg=ngpg/Kg
empty-unit probability Pr(X=0) e−λg under the Poisson model
leaf benefit Vg(Kg) skipped-record volume, ng times that empty-unit probability

On this page λ is only the Poisson parameter. The formal statement's layout letter is written in words. The leaf benefit, exact under the Poisson model, is

Vg(Kg)=ng⋅Pr(X=0)=nge−λg=nge−ngpg/Kg

A finer packing lowers λg and raises the empty-unit probability, so the same group can return a larger leaf benefit at a larger container count. The allocation question is then

max{Kg}∑gVg(Kg)subject to∑gKg≤B,Kg≥1.

The input is the grouping and the observed query-level selection history. For each query, the history says which events inside each group were selected; those counts set the group-wide rate (pg, defined in this section). The benchmark harness is where a physical assignment is replayed and scored against the aggregate waste of that assignment (defined in Problem Statement's formal statement, §2.5). Discrete upgrades may leave some of the ceiling unused when the next option is larger than the remainder.

A split tree becomes a storage plan only after the container-count ceiling (B, defined in this section) and the size floor have been applied. Section 2 writes that step as a knapsack.

2. Problem Generalization: Multiple-choice Knapsack

The allocation in §1 is a multiple-choice knapsack problem. In the ordinary knapsack, one bag has a capacity, each item has a weight and a value, and the solver packs a subset that fits. The multiple-choice variant adds classes: the items are grouped, and the solver takes exactly one item from each class.

term symbol meaning
capacity B the container-count ceiling from §1
class g one terminal group; the solver chooses exactly one option from this class
option (Kg,j,Vg,j) one final container count and its estimated skipped-record value for group g
weight Kg,j how much of the ceiling that option consumes
value Vg,j the leaf benefit from §1, ng⋅Pr(X=0)
growth factor r>1 the multiplier that steps from one option to the next in a group's chain
group count cap Kg,max largest count the ceiling and the size floor still allow for group g

Listing every integer count between 1 and Kg,max would make a large option set. A geometric series keeps a short upgrade chain. Starting from one container, multiply by the growth factor (r, defined in this section) until the group's count cap is reached:

Kg,j∈{1,r,r2,…},Kg,j≤Kg,max.

The factor and the cap are modeling choices. The ladder is sparse: it samples a few increasingly fine packings rather than every intermediate count.

term symbol meaning
upgrade edge j→j+1 the predecessor-constrained step from one option to the next in the same group
additional containers ΔKg,j Kg,j+1−Kg,j
marginal benefit ΔVg,j Vg,j+1−Vg,j, the incremental estimated skipped-record volume from the higher count
marginal efficiency eg,j estimated benefit per additional container, ΔVg,j/ΔKg,j

For each neighboring pair,

ΔKg,j=Kg,j+1−Kg,j,ΔVg,j=Vg,j+1−Vg,j,eg,j=ΔVg,jΔKg,j.

A later option replaces the earlier option for the same group. An upgrade to Kg,j+1 is reachable only after the chain has paid for the preceding count. The knapsack chooses one option per class. An incremental implementation consumes a prefix of that class's edge chain. Marginal efficiency (eg,j, defined in this section) puts those prefixes on one axis: estimated skip per added container.

3. Greedy Optimization

A standard near-optimal procedure is a greedy scan that repeatedly accepts the currently exposed upgrade with the highest marginal efficiency that still fits the remaining ceiling. The values it ranks are the leaf benefits (Vg(Kg)=ng⋅Pr(X=0), defined in §1). When resource can be added one unit at a time, and every group's next marginal gain is no larger than its previous one, that scan is optimal. Federgruen and Groenevelt state the conditions in The Greedy Procedure for Resource Allocation Problems: Necessary and Sufficient Conditions for Optimality. This page does not prove the theorem. The useful fact is the condition: each chain must expose diminishing marginal returns in increments the allocator can actually take.

term symbol meaning
diminishing marginal returns eg,j+1≤eg,j every later upgrade in one group is no more efficient than the previous one
exposed edge — the next upgrade whose predecessors have already been accepted
group count m number of terminal groups in the split
upgrade-edge count E number of predecessor-constrained steps across all groups

After the option values are known, a binary heap of the m currently exposed edges makes each accept O(log⁡m). At most E accepts occur, so the scan is O(E⁡log⁡m) time and O(m) extra space, plus O(E) to hold the ladders. Enumerating every combination of one option per group grows as Jm, where J is the length of a ladder.

The geometric model does not guarantee the theorem's conditions. An edge can consume several containers at once, so it is indivisible, and taking the highest ratio first can leave a remainder that another combination would have used. The ladder also skips intermediate counts. A modest first upgrade can hide a later edge whose efficiency is higher; a scan that ranks only currently exposed edges may spend the ceiling elsewhere before that later edge appears.

The option values belong to one static sample. Group sizes and query selections can change after the sample is taken, and new groups each claim a first container. The greedy result is then a cheap static estimate of skipping potential, useful as a cost-versus-benefit threshold and without a general optimality guarantee.

Three guardrails keep an offered count inside the theorem's region and inside what a real data storage system will hold.

term symbol meaning
starting count Kg,0 first offered container count, at or above the inflection ngpg/2
skip bar — group-level empty-unit probability required before Kg>1 is granted; a typical engine bar is about 50%

The first offered count on a group's ladder is Kg,0=ngpg/2, or the next integer above that. There the Poisson parameter (λg, defined in §1) equals 2 and the empty-unit probability (Pr(X=0), defined in §1) is e−2≈13.5%. From that count onward the leaf benefit is concave in Kg, so marginal efficiency (eg,j, defined in §2) decays. If ngpg/2 is less than 1, the one-container floor is already past the inflection. If the starting count exceeds the largest Kg the size floor allows, the group stays at one container and receives no upgrades.

The size floor (smin, defined in §1) still bounds the top of the chain: ng/Kg>smin. That small-container bound keeps metadata and file count from growing without a matching volume per container.

Grant Kg>1 only when that group's empty-unit probability clears the engine's break-even for a skip structure against a full table scan. A typical bar is about 50%, which is λg=ln⁡2 and a count near 1.44ngpg. Treat 50% as a typical engine bar, not a constant this page ships. That bar is the cost-versus-benefit threshold from §1, and it is stricter than the 13.5% inflection: a ladder can already be concave and still fail to pay for an index. A group can clear the starting count and miss the skip bar, or clear both and still hit the size floor.
