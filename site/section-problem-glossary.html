Terminology

Term Definition
Event / record A stored item in the corpus. The statement uses event; record names the same object.
Corpus (E) The finite set of all stored events.
Container (c) A storage unit that holds a subset of events and is fetched whole. One fetch returns every event in the container.
Container capacity How many events one container holds. Capacity stays between storage-system lower and upper bounds so a fetch is neither too small to amortize nor so large that almost every query activates it.
Layout (λ) The assignment of every event to exactly one container. The containers therefore partition the corpus.
Query A database request that retains selected events by fetching entire containers.
Selected events (Sq) The events a query ultimately needs — the events it selected.
Index table (I) A narrow table with one row per event. A query scans it to resolve which containers to fetch before any container is opened.
Activation A container is activated when it holds at least one selected event. Every activated container must be fetched.
Materialized volume (Mq) Every event in every container the query activates — the volume the fetch returns, including events the query will discard.
Skipped container A container that holds no selected event. It is not fetched.
Waste (wq) Materialized events the query did not select — the difference between materialized volume and the selected-event count.
Aggregate waste (𝒲(λ)) The sum of per-query waste over the observed workload. The objective is to choose a layout that minimizes this sum.
Selection log (L) The observed relation of which query selected which event. One row is one selection; absence means the query did not select the event.
Assignment strategy The rule that decides which events share a container — the procedure that produces a layout.
