1. Explore Data Split Trees

With a quantified data-skipping goal in place, a split search looks for a partition of the input dataset with the highest data-skipping potential. It grows that partition as a logical tree and scores its leaves. Exact search is exponential in the corpus, so a solver with a limited search budget uses heuristics to find a less costly, suboptimal tree.

The search begins with the entire corpus in one leaf. Cutting a leaf into two or more children grows the grouping S; a cut may have more than two branches. Each child is then packed into equal-size containers. Fitness scores either that packing or the tree with the new children in place. The fitness of a leaf scores its packing without another cut. OPT of the leaf is the best score reachable if further cuts are allowed under the remaining evaluation budget. Every leaf uses the same container size, the common packing budget. Compute and wall-clock limits are shared evaluation budgets: they restrict the cuts the search can examine, rather than the container size. Each leaf is a subproblem defined by its events and that shared container size. Given the same remaining evaluation budget, leaves with identical contents are the same subproblem regardless of the path that produced them.

term symbol meaning
grouping S a partition of the events under consideration into terminal groups
fitness of a leaf v(ℓ) the leaf scored as packed at size s, with no further cut
OPT of a leaf OPT(ℓ) the best score obtainable from the leaf if further cuts remain allowed under the remaining evaluation budget
cut γ a partition of one leaf into two or more children
children of a cut C(γ) the groups a cut γ produces
leaf event count nℓ events in the leaf being cut
child event count nc events in child c, so nc/nℓ is that child’s population weight
container size s event count of one packed container; the common packing budget
evaluation budget — compute and wall-clock allowed for enumerating and scoring cuts

From any leaf, finding the best remaining cuts repeats the search that began with the whole corpus. The parent leaf’s potential can therefore be written in terms of its immediate children:

OPT(ℓ)=max(v(ℓ),maxγ∑c∈C(γ)ncnℓOPT(c))

The incremental value of a cut is the potential its children add beyond leaving the leaf packed. When they add no value, the recurrence keeps the packed fitness.

This recurrence describes exact dynamic programming on the tree, but it does not make the search tractable: the possible leaf contents form an exponential state space. The notation leaves implicit how the shared remaining evaluation budget is allocated among children; OPT refers to the best continuation feasible within that budget. The figure Recursive Partitioning with a Decision Tree shows a cycle of listing cuts, scoring them, and replacing a leaf. The fitness v(ℓ) remains abstract here; Section 3 gives it three concrete interpretations.

2. Practical Consideration

Searching for a better layout costs compute and time; the expected return is I/O saved by later queries. Because the state space in §1 is exponential, a storage system searches within a limited evaluation budget while keeping container size s (defined in §1) fixed. It retains a cut when the fitness gain per extra group is large enough.

term symbol meaning
extra groups Δk how many groups the cut adds; a binary cut has Δk equal to 1
incremental gain Δv/Δk fitness change per extra group

A greedy top-down baseline accepts one cut at a time. While evaluation budget remains, it takes a locally improving cut when its incremental gain (Δv/Δk, defined in this section) is large enough.

If budget remains, the search can explore other candidate trees. The following techniques can be combined:

  • simulated annealing and evolutionary search balance exploitation against exploration.
  • beam search or a priority queue keeps several intermediary solutions.
  • A published query-data tree (qd-tree) study grows a layout tree so later queries can skip more of the table (Yang, Ding, Chaudhuri, and Argyraki, Qd-tree: Learning Data Layouts for Big Data Analytics, arXiv:2004.10898).

Search incurs compute and time costs when the layout is built or rebuilt. Its expected payoff comes from future I/O the layout avoids. That payoff depends on the deployed data-retention policy: a short retention window leaves fewer future fetches over which to recover the search cost. This page does not select, rank, or recommend a search method.

3. Choosing a Value function to Optimize

Section 1 leaves leaf fitness (v(ℓ), defined there) abstract. The three measures below can each serve as its value function when screening a logical grouping. The benchmark harness scores a physical layout by replay instead. These measures are distinct from the aggregate waste of a physical assignment (defined in Problem Statement’s formal statement, §2.5).

3.1 Group-wide skipping ratio

After a leaf is packed at size s, the group-wide skip ratio estimates the share of events a later query would leave unread. Each packed container receives one selection rate: the average fraction of its events selected across training queries.

term symbol meaning
grouping S a partition of the events under consideration into terminal groups
parent event count n the sum of the container event counts
container i one of the equal-size containers after the grouping is packed at size s
container event count ni events in container i; equal-size packing means ni equals s
per-query selected count kq,i how many events training query q selected in container i
group-wide rate pg,i pg,i=avgqkq,ini
population weight wi wi=nin
group-wide Poisson parameter λi λi=nipg,i=avgqkq,i
group-wide skip ratio Vmarg(S,s) estimated skip ratio from the group-wide rates

A query skips a container when it selects no event in it. Assuming independent selection, the empty-container probability is (1−pg,i)s. At a small selection rate, its Poisson approximation is e−λi. Weighting these probabilities by container population gives the exact and approximate skip ratios:

Vmarg(S,s)=∑iwi(1−pg,i)s≈∑iwie−λi

The exact and approximate ratios both lie between zero and one. Here, the subscript identifies the group-wide rate; it does not denote incremental gain. Fitness depends on container size s: finer packing changes the empty-container curve. The score also loses query-specific patterns. Workloads with the same average rate in each container score alike, even if different queries hit different containers.

3.2 Query-conditional skipping ratio

The query-conditional skip ratio uses the empty-container model from §3.1 while retaining a selection rate for each query. The group-wide measure instead averages those rates into one value per container.

term symbol meaning
query-conditional rate pi,q pi,q=kq,ini
per-query Poisson parameter λi,q λi,q=kq,i
query count Q number of training queries
query-conditional skip ratio V(S,s) estimated skip ratio that keeps the query index

Weighting each query’s empty-container probabilities by container population, then averaging across training queries, gives:

V(S,s)=(1/Q)∑q∑iwi(1−pi,q)s≈(1/Q)∑q∑iwie−λi,q

Both the exact and approximate ratios lie between zero and one. When a query never touches a container, that container contributes its full population weight (wi, defined in §3.1). A cut that isolates a block avoided by some queries can therefore raise V(S,s), even if the group-wide rates (pg,i, defined in §3.1) are even across containers. This measure retains which containers each query touches, though it does not track which selected events share a container.

3.3 Weighted Gini

The Gini coefficient measures how unevenly a non-negative quantity is distributed across a population. A value near zero means an even distribution; a larger value means more of the total belongs to a smaller share of the population (Gini coefficient).

Here, weighted Gini measures the distribution of the group-wide rate (pg,i, defined in §3.1) across containers. A container with a lower rate counts as poorer.

term symbol meaning
population weight wi wi=nin, as defined in §3.1
usage share qi qi=nipg,i∑jnjpg,j. This qi is a usage share, not a query index; Q remains the query count from §3.2
cumulative usage share CumQi a running sum of usage shares from the poorest container through i, not a sum over the Q queries
weighted Gini G(S) inequality of the group-wide rate across containers
incremental Gini gain ΔG/Δk Gini change per extra group

Sort containers from the lowest to the highest group-wide rate (pg,i, defined in §3.1). Weighted Gini is then:

G(S)=1−∑iwi(2·CumQi−qi)

Before any split, every container has the same rate, so G(S) is zero. A cut can raise G(S) when usage becomes concentrated in a small share of the population. To weigh that change against the extra groups it creates, the search compares incremental Gini gain (ΔG/Δk, defined in this section). The score G(S) measures inequality in usage across containers; it is not a skip ratio.
