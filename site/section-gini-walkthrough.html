1. Explore Data Split Trees

After defining a quantified data skipping goal, the research starts with a split search that identifies a partition of the input dataset that maximizes a value function, data-skipping potential. The search grows that partition as a logical tree and scores each leaf. Exact search for that partition is exponential in the corpus, so a cost-limited solver uses heuristics that return a cheaper, sub-optimal tree.

A split search starts with the whole corpus as one uncut group, a leaf, and grows a grouping S by cutting a current leaf into two or more children. A cut may be multi-way. After a cut, each child is packed into equal-size containers. A fitness is a number on that packing, or on the tree after the leaf is replaced. The fitness of the leaf is that packing scored with no further cut. OPT of the leaf is the best score still reachable from that leaf if further cuts remain allowed under the remaining evaluation budget. Every leaf packs at the same container size, the common packing budget. Compute and wall-clock are common evaluation budgets: they limit how many cuts are enumerated, not the packing. Each leaf is a subproblem on its own events plus that shared container size. Two leaves with the same contents are the same subproblem, regardless of the path that produced them.

term symbol meaning
grouping S a partition of the events under consideration into terminal groups
fitness of a leaf v(ℓ) the leaf scored as packed at size s, with no further cut
OPT of a leaf OPT(ℓ) the best score obtainable from the leaf if further cuts remain allowed under the remaining evaluation budget
cut γ a partition of one leaf into two or more children
children of a cut C(γ) the groups a cut γ produces
leaf event count nℓ events in the leaf being cut
child event count nc events in child c, so nc/nℓ is that child’s population weight
container size s event count of one packed container; the common packing budget
evaluation budget — compute and wall-clock allowed for enumerating and scoring cuts

Finding the best remaining cuts from an arbitrary leaf is the same search as the one that started at the corpus. The potential of a parent leaf can be expressed by the potentials of its immediate children:

OPT(ℓ)=max(v(ℓ),maxγ∑c∈C(γ)ncnℓOPT(c))

A cut’s incremental value is the extra potential those children return over leaving the leaf packed. If the children do not raise the score, the recurrence keeps the packed fitness.

That recurrence is the meaning of exact dynamic programming on the tree. The state space of possible leaf contents is exponential in the corpus, so the recurrence defines the problem; it does not claim a tractable solver. 2. Practical Consideration

A real data storage system has to balance the cost of searching for a better layout against the I/O that layout is expected to save. It does not enumerate the exponential state space of §1. It spends a limited compute and time budget, at a fixed container size (s, defined in §1), to grow a tree whose later avoided I/O can repay the search. A cut is kept when the fitness change per extra group is large enough.

term symbol meaning
extra groups Δk how many groups the cut adds; a binary cut has Δk equal to 1
incremental gain Δv/Δk fitness change per extra group

A cheap greedy top-down baseline grows the tree one accepted cut at a time, taking a locally improving cut while evaluation budget remains and incremental gain (Δv/Δk, defined in this section) is large enough.

Leftover budget can be spent looking for improvement in other directions. These techniques can be combined.

  • simulated annealing and evolutionary search balance exploitation against exploration.
  • beam search or a priority queue keeps several intermediary solutions.
  • A published query-data tree (qd-tree) study grows a layout tree so later queries can skip more of the table (Yang, Ding, Chaudhuri, and Argyraki, Qd-tree: Learning Data Layouts for Big Data Analytics, arXiv:2004.10898).

The compute and time spent searching are paid once, or on a rebuild, and recovered from expected future I/O that the layout avoids. Return on that investment is bounded by the data-retention policy in the deployed environment: a short retention window leaves fewer future fetches against which to charge the search. This page does not select, rank, or recommend a search method.

3. Choosing a Value function to Optimize

The recurrence in §1 leaves the fitness of a leaf (v(ℓ), defined in §1) as an abstract value function. The three readings below are candidate value functions for that fitness. They screen a logical grouping; a physical layout is scored by replay in the benchmark harness. None of them equals the aggregate waste of a physical assignment (defined in Problem Statement’s formal statement, §2.5).

3.1 Group-wide skipping ratio

The group-wide skip ratio estimates the share of events a later query would leave unread after the leaf is packed at s. It gives each packed container one selection rate: the average, across training queries, of the fraction of that container each query selected.

term symbol meaning
grouping S a partition of the events under consideration into terminal groups
parent event count n the sum of the container event counts
container i one of the equal-size containers after the grouping is packed at size s
container event count ni events in container i; equal-size packing means ni equals s
per-query selected count kq,i how many events training query q selected in container i
group-wide rate pg,i pg,i=avgqkq,ini
population weight wi wi=nin
group-wide Poisson parameter λi λi=nipg,i=avgqkq,i
group-wide skip ratio Vmarg(S,s) estimated skip ratio from the group-wide rates

A container is skipped when it holds no selected event. Under independent selection that empty-container probability is (1−pg,i)s. When the rate is small, the Poisson approximation of that empty-container probability is e−λi. The population-weighted skip ratio, exact and approximate, is

Vmarg(S,s)=∑iwi(1−pg,i)s≈∑iwie−λi

Both forms lie in the unit interval. The subscript names the group-wide rate, not an incremental gain. The fitness depends on s: a finer packing changes the empty-container curve. Because every query is collapsed into one rate per container, two workloads that match on those averages receive the same score, even when they hit different containers on different queries.

3.2 Query-conditional skipping ratio

The query-conditional skip ratio uses the same empty-container model as the group-wide skip ratio (defined in §3.1), but keeps one selection rate per query instead of one query-averaged rate per container.

term symbol meaning
query-conditional rate pi,q pi,q=kq,ini
per-query Poisson parameter λi,q λi,q=kq,i
query count Q number of training queries
query-conditional skip ratio V(S,s) estimated skip ratio that keeps the query index

The population-weighted skip ratio, exact and approximate, is

V(S,s)=(1/Q)∑q∑iwi(1−pi,q)s≈(1/Q)∑q∑iwie−λi,q

Both forms lie in the unit interval. A query that never touches a container contributes that container’s full weight (wi, defined in §3.1) to the skip ratio. A cut that isolates a block some queries never enter can therefore raise V(S,s) even when the group-wide rates (pg,i, defined in §3.1) are even across containers. The query-conditional skip ratio does not use which selected events share a container.

3.3 Weighted Gini

The Gini coefficient summarizes how unevenly a non-negative quantity is shared across a population: a value near zero is even, and a larger value means a smaller share of the population holds more of the total (Gini coefficient).

The weighted construction used here measures how unevenly the group-wide rate (pg,i, defined in §3.1) sits across containers. A container with a smaller rate is poorer.

term symbol meaning
population weight wi wi=nin, as defined in §3.1
usage share qi qi=nipg,i∑jnjpg,j. This qi is a usage share, not a query index; Q remains the query count from §3.2
cumulative usage share CumQi a running sum of usage shares from the poorest container through i, not a sum over the Q queries
weighted Gini G(S) inequality of the group-wide rate across containers
incremental Gini gain ΔG/Δk Gini change per extra group

Sort containers poorer-then-richer by the group-wide rate (pg,i, defined in §3.1). Then

G(S)=1−∑iwi(2·CumQi−qi)

On the unsplit corpus every container shares one rate, so G(S) is zero. After a cut, G(S) is large when a small population share holds most of the usage. A search that charges for extra groups compares the incremental Gini gain (ΔG/Δk, defined in this section). G(S) screens inequality. It is not a skip ratio.
