1. Working with Storage Container Limits

Measuring Data Layout Fitness grows a split tree by cutting leaves and scores the resulting groups for data-skipping potential. The tree helps screen for where selection concentrates. Its terminal groups still need an assignment to containers that the storage system can maintain.

The medicine-cabinet walkthrough in Problem Statement makes the count limit concrete. Each small drawer represents one container. Because the cabinet has a fixed number of drawers, the dispensary cannot reserve one for every medicine. A data table faces the same limit on its containers.

A storage container might be an SSD block, a file, a partition, or an object in cloud storage. Keeping each one addressable has a metadata cost. The model therefore uses a container-count ceiling, such as a maximum number of files or partitions per table, and a soft size floor, such as a minimum byte size for an S3 object.

Within the count ceiling and size floor, the allocation seeks the greatest estimated data skipping. This page models that choice as a multiple-choice knapsack on a static sample of queries. Its numeric result belongs to the frozen profile and may not transfer to a live system. It can still suggest a cost-versus-benefit threshold on the observed log: how much additional skipping the next increment of container count appears to buy.

term symbol meaning
terminal group g one population produced by the already-chosen logical split
group population ng number of events in group g
container count Kg number of containers assigned to group g
container-count ceiling B maximum number of containers the system will keep for the table
container-size floor smin smallest container the system will accept; it caps how large Kg can grow

Each terminal group first needs one container to stay addressable. The groups share any capacity left under the count ceiling, while the size floor (smin, defined in this section) limits how finely each one can be packed.

Packing group g into Kg equal containers gives each one size ng/Kg. Measuring Data Layout Fitness §3.1 uses the empty-container Poisson probability to score a packed leaf. Here, that probability becomes a volume: the leaf benefit is the group’s event count multiplied by the chance that a container holds no selected event.

term symbol meaning
group-wide rate pg average, across training queries, of the fraction of group g each query selected
selected count in a container X how many events a later query selects in one packed container of the group
Poisson parameter λg expected selected-event count in one container, λg=ngpg/Kg
empty-container probability Pr(X=0) e−λg under the Poisson model
leaf benefit Vg(Kg) skipped-record volume, ng times that empty-container probability

On this page, λ denotes only the Poisson parameter; the formal statement’s layout letter is written in words. Under the Poisson model, the leaf benefit is:

Vg(Kg)=ng⋅Pr(X=0)=nge−λg=nge−ngpg/Kg

Giving a group more containers makes each one smaller. That lowers λg and raises the chance that a container is empty for a query, increasing the group’s modeled leaf benefit. The allocation therefore asks:

max{Kg}∑gVg(Kg)subject to∑gKg≤B,Kg≥1.

The model starts with a grouping and observed query-level selection history. For each query, selected-event counts within each group determine the group-wide rate (pg, defined in this section). The benchmark harness separately replays a physical assignment and scores its aggregate waste (defined in Problem Statement’s formal statement, §2.5). Because upgrades are discrete, the next option may exceed the remaining ceiling and leave some capacity unused.

Applying the container-count ceiling (B, defined in this section) and size floor turns a split tree into a feasible storage plan. Section 2 expresses that allocation as a knapsack.

2. Problem Generalization: Multiple-choice Knapsack

The allocation in §1 is a multiple-choice knapsack problem. An ordinary knapsack has one capacity limit; each item has a weight and a value, and the solver chooses a subset that fits. In the multiple-choice version, items belong to classes, and the solver chooses exactly one option from each class.

term symbol meaning
capacity B the container-count ceiling from §1
class g one terminal group; the solver chooses exactly one option from this class
option (Kg,j,Vg,j) one final container count and its estimated skipped-record value for group g
weight Kg,j how much of the ceiling that option consumes
value Vg,j the leaf benefit from §1, ng⋅Pr(X=0)
growth factor r>1 the multiplier that steps from one option to the next in a group's chain
group count cap Kg,max largest count the ceiling and the size floor still allow for group g

Offering every integer count from 1 through Kg,max would create a large choice set. Instead, each group gets a short geometric upgrade chain: start with one container and multiply by the growth factor (r, defined in this section) until reaching the group’s count cap.

Kg,j∈{1,r,r2,…},Kg,j≤Kg,max.

The growth factor and cap are modeling choices. This sparse ladder offers increasingly fine packings while omitting intermediate counts.

term symbol meaning
upgrade edge j→j+1 the predecessor-constrained step from one option to the next in the same group
additional containers ΔKg,j Kg,j+1−Kg,j
marginal benefit ΔVg,j Vg,j+1−Vg,j, the incremental estimated skipped-record volume from the higher count
marginal efficiency eg,j estimated benefit per additional container, ΔVg,j/ΔKg,j

Each neighboring pair of options has a container cost, an estimated gain, and a gain per added container:

ΔKg,j=Kg,j+1−Kg,j,ΔVg,j=Vg,j+1−Vg,j,eg,j=ΔVg,jΔKg,j.

For each group, the knapsack selects one final option. To reach Kg,j+1, an incremental allocator must first take every earlier upgrade in that group’s chain; those edges form a prefix. Each new option replaces the previous count for that group. Marginal efficiency (eg,j, defined in this section) compares exposed upgrades by estimated leaf benefit per added container.

3. Greedy Optimization

A greedy scan repeatedly takes the exposed upgrade with the highest marginal efficiency that fits the remaining ceiling. It derives those rankings from the leaf benefits (Vg(Kg)=ng⋅Pr(X=0), defined in §1). The scan is optimal when resources can be added one unit at a time and each group’s next marginal gain is no larger than its previous gain. Federgruen and Groenevelt state these conditions in The Greedy Procedure for Resource Allocation Problems: Necessary and Sufficient Conditions for Optimality. This page uses the conditions without proving the theorem. They require diminishing marginal returns in increments the allocator can actually take.

term symbol meaning
diminishing marginal returns eg,j+1≤eg,j every later upgrade in one group is no more efficient than the previous one
exposed edge — the next upgrade whose predecessors have already been accepted
group count m number of terminal groups in the split
upgrade-edge count E number of predecessor-constrained steps across all groups

Once option values are known, a binary heap holds the m exposed edges. Accepting one costs O(log⁡m); at most E can be accepted. The scan therefore takes O(E⁡log⁡m) time and O(m) extra space, with another O(E) to store the ladders. By comparison, enumerating every combination of one option per group grows as Jm, where J is the length of a ladder.

The geometric ladder does not automatically meet the theorem’s conditions. An upgrade may require several containers at once. Choosing the highest efficiency ratio can then strand capacity that another combination could use. The ladder also skips intermediate counts, and a modest first upgrade may hide a more efficient later edge. Because the scan sees only exposed edges, it may allocate the remaining containers elsewhere before that edge becomes available.

Option values come from one static sample. Later changes in group size or query selection can change those values, and each new group claims a first container. The greedy result is therefore a cheap estimate for the sampled workload. It can suggest a cost-versus-benefit threshold, but carries no general optimality guarantee.

Three practical guardrails restrict the counts the allocator offers: a starting count in the concave part of the benefit curve, a minimum container size, and a skip bar. The geometric ladder still has indivisible upgrades.

term symbol meaning
starting count Kg,0 first offered container count, at or above the inflection ngpg/2
skip bar — group-level empty-container probability required before Kg>1 is granted; a typical engine bar is about 50%

The continuous starting target is Kg,0=ngpg/2; the first offered integer count rounds that target up. At the target, the Poisson parameter (λg, defined in §1) is 2 and the empty-container probability (Pr(X=0), defined in §1) is e−2≈13.5%. Rounding upward makes the parameter at most 2 and the probability at least that value. From the offered count onward, leaf benefit is concave in Kg, so marginal efficiency (eg,j, defined in §2) declines. If ngpg/2 is below 1, the one-container floor is already past the inflection. If the rounded starting count exceeds the largest Kg allowed by the size floor, the group stays at one container without upgrades.

The size floor (smin, defined in §1) also caps the chain: ng/Kg>smin. This keeps metadata and file counts from growing without enough volume in each container.

Grant Kg>1 only when the group’s empty-container probability clears the chosen break-even bar for a skip structure against a full table scan. A practical working bar is about 50%. Under the Poisson model, its boundary is λg=ln⁡2, reached at a count near 1.44ngpg; counts that clear the bar have a smaller parameter. The 50% value is a working choice for the observed sample, with no reduction in the modeled objective assumed for that choice. It marks the cost-versus-benefit threshold from §1 and is stricter than the 13.5% inflection: a concave ladder may still fail to pay for an index. A group can reach the starting count and miss the skip bar, or clear both and still be stopped by the size floor.
